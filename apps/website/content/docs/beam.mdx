title: Beam
description: Passkey-signed membership and WireGuard tunnels for the machines you own.
---

Beam connects one person's machines into a fleet. From any member you can
open a shell on another, run a command there, or queue a message until it
connects. n10 Desktop uses Beam to run agents on your other machines.

Each machine holds its own WireGuard node key. A passkey scoped to
`beam.n10.is` signs a WebAuthn assertion for each membership or revocation
statement. The assertion's challenge commits to the statement, including a
joining machine's public key and address. Peers verify it and proof that the
machine holds the matching node key before accepting a connection.

The passkey's PRF supplies a secret from which Beam derives a directory
encryption key and read token. Machines encrypt membership and revocation
records locally with XChaCha20-Poly1305. The Cloudflare Worker at
[beam.n10.is](https://beam.n10.is) stores those records and checks an
assertion before each append. It sees fleet IDs, statement hashes, assertions,
request metadata, record sizes and timing, but cannot read the records or
mint a signed member.

[Tailcat](https://github.com/tailscale/tailcat) connects members with
WireGuard, directly where possible and through a DERP relay otherwise. The
relay sees endpoint IPs and packet metadata, but not shell, command or
message contents. The directory worker does not carry that traffic. Beam
does not require a Tailscale account.

## Trust and limits

The worker also serves the passkey ceremony page. During an approval, that
page requests the signature and sees the PRF result. It seals one result to
the initiating machine through a one-time worker slot; the worker holds only
the sealed result. A compromised page can choose one statement for that tap;
on a machine's first enrolment it can substitute the fleet root the machine
pins. Approve only a ceremony you started, show its QR code privately, and
compare a joining machine's fleet fingerprint with `beam status` on an
existing member.

Revocation applies locally at once and spreads to connected peers. Offline
peers learn it later, and the directory can withhold records, so a new machine
may temporarily admit a revoked key. A revoked machine retains directory read
access. By default, a member can open a shell as the daemon's user on other
members; if one is compromised and copies their keys, start a new fleet.

Beam is in beta. The source and [full trust model](https://github.com/notaharness/beam/blob/main/docs/01-model.md)
are in the beam repository.

## Install

n10 Desktop includes Beam for its [Fleet section](/docs/guides/fleet), so you
don't need Beam to use Fleet. The `beam` command is on the `PATH` only in
terminals and sessions n10 Desktop starts. Install it yourself to use `beam`
from any shell, or on machines without n10 Desktop, such as a headless build
box. It runs on macOS and Linux, arm64 and x64.

You need a passkey provider that supports the WebAuthn PRF extension, in a
browser or on your phone.

```sh
npm install -g @notaharness/beam
```

## Use it

Create the fleet on your first machine, then join each of the others:

```sh
beam init --label laptop     # on the first machine: two passkey prompts
beam join --label buildbox   # on every other machine: one passkey prompt
```

Each prompt opens a browser, or on a headless machine draws a QR code to scan
with your phone. After joining, compare the fleet fingerprint that
`beam join` prints with `beam status` on a machine already in the fleet.
They must match.

Then, from any machine:

```sh
beam peers                                   # the fleet and who is online
beam connect buildbox                        # a shell on buildbox
beam exec buildbox -- uname -a               # one command, with its exit code
beam msg send buildbox --topic jobs 'ready'  # delivered now, or when buildbox connects
beam msg listen --topic jobs                 # on buildbox: print incoming messages
```

A shell ends when the connection does, so run long-lived work in tmux:
`beam connect buildbox -- tmux new-session -A -s agents`.

By default every machine in the fleet can run commands as you on every
other. Run `beam --help` for every command, including limiting and revoking
machines.

## With n10 and Orchestra

n10 Desktop's [Fleet section](/docs/guides/fleet) manages the fleet and
launches agents on its machines, and [Orchestra](/docs/orchestra)'s scripts
take `--machine NAME` to run a player on one; that machine needs Orchestra
installed too.
