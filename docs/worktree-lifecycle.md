## Identity and discovery

A worktree is a checkout directory, independently of its branch and its agent.
The internal key is `(worktree, canonical repo root, canonical checkout path)`;
branch names and tmux session names are labels. A symlink alias resolves to the
same physical identity. A directory move changes that identity; see
[Relocation](#relocation) for how a moved checkout keeps its agent.

`listWorktrees` reads Git's porcelain list and keeps only paths owned by the
configured resolver: `.claude/worktrees/` by default, or `worktreePath` from the
project configuration. A worktree made by plain Git **inside that directory**
is discoverable. An arbitrary sibling checkout outside the configured directory
is not listed. The main checkout is outside this default discovery scope.

The shared scanner polls every four seconds and also watches the resolver's base
directory with a 200 ms debounce. The watch accelerates creation; it does not
recursively watch branch changes. Discovery joins worktrees with tagged tmux
sessions by checkout path, adopts live sessions, and reports appeared, disappeared,
switched and ended keys. Untagged tmux sessions are foreign. Initial worktree lists
come from each shell; initial session adoption is still a discovery operation.

A Desktop sidebar row exists for every listed worktree. Creating a worktree opens
a tab; merely discovering an idle worktree adds a row, and selecting it opens a
preview. Live agents auto-open tabs. A stopped agent does not imply a removed
worktree. TUI rows show filled icons (`◉`/`●`) for running agents and hollow icons
(`◎`/`○`) otherwise; selection chooses between the two forms.

## Relocation

A moved checkout ([#208](https://github.com/notaharness/n10/issues/208)) keeps
its agent by rebinding the session's tags, never by matching a branch or a
label. Each discovery scan checks every live, local worktree session whose
tagged checkout no longer exists. tmux reads the pane process's working
directory from the kernel (`#{pane_current_path}`), and that directory follows a
rename. When it is exactly the root of a checkout Git lists for the open
repository, no other session's tags claim that checkout, and this process holds
no connection under the old key, the scan rewrites `@orchestra-worktree-path` and
`@orchestra-repo` in one tmux command and adopts the session as usual
([`rebindMovedSessions`](../libs/core/src/lib/discovery/moved-sessions.ts), run
by `observeTmuxSessions`). This covers a renamed repository after
`git worktree repair` and `git worktree move`.

Anything else stays unbound. A copied checkout is a new directory, and an agent
that left its checkout root or whose directory was deleted gives no evidence. Its
session remains an orphan and the checkout is new. Without a live pane there is
no kernel evidence, so a retained dead pane is not rebound.

n10 does not follow a repository that moves while it is open: the cached root,
resolver and directory watch keep referring to the old path. Reopen the
repository at its new location after `git worktree repair` (Desktop: open it;
TUI: restart there). The first scan rebinds the surviving agents. A session the
running process still holds under its old key is left alone until a new process
owns it, so one process never attaches twice.

  adoption/launch needs checkout-path addressing across discovery, launch and editor
  actions. Its discovery/contract changes overlap #205/#206, so they stay separate.
- [#56](https://github.com/notaharness/n10/issues/56): master has bounded TUI exit
  and C11 passes with a running agent; the reported hang does not reproduce on this baseline.
- Removal rows are assigned to #205/#206, not reimplemented by this test change.
  This table does not claim those PRs test deletion of the entire repository.

All sessions use the fixtures' HOME and validated scratch socket environment,
with `TMUX` unset. Server recreation ends individual fixture sessions and checks
that a subsequent server has a different PID; it never calls `kill-server` or
reaches the user's socket. Restart tests launch a new host/TUI process, not just
a renderer reload. Follow [testing.md](testing.md) for the fixture and runner contracts.
